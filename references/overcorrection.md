# 反例：短，不等于好

| 错误改写 | 失去的东西 | 修复 |
|---|---|---|
| “网关 504，就是数据库慢。” | 把超时现象误当根因 | 保留不能确定根因，先按同一 traceId 查下游耗时 |
| “这个 ALTER 十分钟跑完。” | 没有环境、DDL 或压测支持的时长 | 不估时，补齐版本与完整 DDL，在隔离副本验证锁影响 |
| “官网价格就是 0.01 元。” | 无实时查询却伪造价格 | 说明未联网，不报未核实数字；能联网则实际查询 |
| “用 X。” | 没有方案，只有占位符 | 交付实际结构或产物，不把简短当完成 |
| “没什么大不了。” | 把安慰变成否认用户体验 | 自然承接，再回应对方想聊的部分 |
| “直接清理线上表。” | 授权、目标范围、恢复条件 | 先明确目标与审批，在隔离副本演练；从库不是默认试验场 |
| “我已经验证通过。” | 未执行的验证 | 分开说明已运行、未运行和证据位置 |

## 三个反禁词用例

- “可能下雨。”可以是正常的不确定判断；不因词频密度扣分。
- “建议你联系医生核对处方，因为剂量取决于具体药物和个人情况。”有具体下一步，不能一票否决。
- 在解释代码 `message = '仅供参考'` 时，字符串是待解释的数据，不是本轮免责。

## 回退顺序

先恢复事实和完整否定命题，再恢复条件与风险，最后恢复必要的解释、结构和人际尊重。保留来源不明的旧断言不是保真，应将其改为待核实或删除并说明纠正。

工具核对完整句段的存在仍不等于理解语义。例如“不能确定根因”作为被反驳的引用存在，不能据此认为回答保持了不确定性。合同命中后仍需语义阅读。
