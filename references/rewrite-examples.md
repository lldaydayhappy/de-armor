# 案例与复现

`assets/cases.json` 是六组示例的唯一来源。每组包含请求、已知上下文、原回复、改写、刻意过度压缩的反例、信息合同和改写理由。

| 场景 | 真正交付 | 不能丢掉 |
|---|---|---|
| 故障排查 | 按 traceId 定位下游耗时的动作 | 观测不是根因；不能直接加超时 |
| 生产变更 | 明确阻塞信息与隔离验证路径 | 无锁表时长依据；不在生产直接试 |
| 方案选择 | 条件明确的选型建议 | 已有技术积累和迁移验证 |
| 模糊需求 | 已能使用的最小原型范围 | 假设、暂缓项、必须有实际方案 |
| 能力边界 | 清楚说明未查询，并提出可完成的比较路径 | 不伪造最新价格或查询结果 |
| 情绪支持 | 自然回应并留出表达空间 | 不把共情当套话，不擅自诊断 |

## 本地复跑

在技能根目录：

```sh
python3 -B scripts/build_demo.py --write
```

第一条运行回归测试；第二条检查页面内嵌证据是否与当前案例和审查器一致；第三条更新内嵌证据。打开 `assets/de-armor-demo.html` 即可离线切换六个案例。

展示页可编辑候选回复并核对合同，也可切换“过度压缩反例”。本地编辑只在当前浏览器页面内存中进行，不上传，不永久保存。页面的交互检查核对字面锚点、禁用断言和新增数字，不调用模型，不伪装成自动语义改写。

## 验收不是“变短多少”

同一合同同时核对原回复、改写和反例：有些改写只是压缩，有些补交付后会变长。字数仅描述长度。

重点看：原答缺的产物有没有补齐；已知、不确定性和边界有没有丢；反例是否被拦住；删改理由是否可信。合同由案例作者声明，命中数量不等于独立测量的事实保真率。

## v1 纠正记录


撤回旧例中的无依据断言：ALTER 必然锁表十分钟、处方必然按某种方式计算、未知源码必然抛某异常。撤回“官方只允许三个目录”的说法：公开规范允许额外目录，scripts/references/assets 是推荐惯例。

保留 v1 备份在模块外，v2 用新的规则编号和报告 schema，避免旧系统把新语义误当旧高分通过。
